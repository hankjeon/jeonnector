# 전연결기(jeonnector) 요구사항 및 화면 설계

> 상태: **확정 (1차 구현 및 신호표 입력·정렬·핀맵 크기 개선 완료)**
>
> 제1~5절은 사용자와 협의해 확정한 요구사항과 화면 설계이며, 제6.1절에는 구현 시 확정한 세부 수치와 구성을 기록한다. 제3.6.1절의 신호표 입력 개선, 제3.6.2절의 할당 변경 후 즉시 정렬과 제4.1절의 좁은 핀맵 구성을 후속 구현했다. 추후 결정할 기능은 제6.2절에 **향후 고려사항**, 후속 구현 결과는 제6.3절에 구분한다.

## 1. 프로젝트 개요 및 목적

연결기(Connector)에 신호(Signal)를 배치할 때는 인접 핀과의 간섭, 전원/접지 분포 등 **신호의 물리적 특성에 따른 공간적 배치**가 중요하다.

프로그램의 한글 이름은 **전연결기**, 저장소 이름은 `jeonnector`이다. 참고 프로그램 `jeonnect`의 한글 이름은 **전연결**이다.

전연결기는 다음 목적을 위해 개발한다.
- 연결기의 물리적 핀 배치(Layout)와 각 핀에 할당된 신호명을 직관적으로 시각화한다.
- 신호유형에 따라 핀 색상을 구분하여 물리적 배치의 적절성을 쉽게 파악하게 한다.
- 핀맵과 신호표를 연동하여 조회와 편집을 빠르게 수행한다.

---

## 2. 용어

문서와 화면은 아래 용어로 통일한다. 코드 식별자는 영문 이름을 기준으로 한다.

| 용어 | 영문 식별자 | 뜻 |
| --- | --- | --- |
| 연결기 | `Connector` | 프로젝트에 추가한 연결기 인스턴스. 하나의 연결기 부품을 사용하거나 아직 부품이 없을 수 있다. |
| 연결기 식별자 | `connector_id` | 연결기의 프로젝트 내 고유 이름(예: `J1`, `J2`, `P1`). |
| 연결기 부품 | `ConnectorPart` | 외형, 핀 번호, 핀 위치 등 물리 정보를 가지는 부품 정의. UUID로 식별한다. |
| 연결기 부품 데이터베이스 | `PartLibrary` | 전연결기가 관리하는 연결기 부품 모음. |
| 연결기 부품 편집기 | `PartEditor` | 연결기 부품을 만들고 수정하는 화면. |
| 핀맵 | `Pinmap` | 연결기의 핀 위치와 할당 상태를 보여주는 그림. |
| 신호표 | `SignalTable` | 선택한 연결기의 신호 목록표. |
| 신호 | `Signal` | 연결기 안에서 신호명을 키로 관리하는 신호. 신호유형과 색상을 속성으로 가진다. |
| 신호유형 | `SignalType` | 전원, 접지 등 신호의 분류. "카테고리" 대신 이 용어를 사용한다. |
| 할당 / 미할당 | `assigned` / `unassigned` | 신호와 핀 번호의 연결 여부. "지정/미지정" 대신 이 용어를 사용한다. |
| 신호 중복 | `duplicate` | 한 핀에 여러 신호가 할당된 오류 상태. |

## 3. 핵심 기능 요구사항

### 3.1 프로젝트와 연결기 관리
- 하나의 프로젝트에 여러 연결기를 추가하거나 제거할 수 있다. 제거할 때는 확인 창을 띄운다.
- 연결기 식별자는 프로젝트 안에서 중복될 수 없으며, 추가 후에도 변경할 수 있다. 문자 규칙은 신호명과 같다(제3.6절).
- 사이드바(제목 "연결기 목록")에는 연결기를 식별자의 자연 정렬 순서로 표시하며, 수동으로 순서를 바꾸지 않는다. 항목에는 연결기 식별자만 표시하고, 신호 중복이 있는 연결기는 빨간 글씨와 `⚠`로 표시하며 건수는 툴팁으로 보여 준다.
- 추가·식별자 변경·제거는 사이드바 우클릭 메뉴로 수행한다. 빈 공간 우클릭은 `연결기 추가`, 연결기 우클릭은 `연결기 추가`·`식별자 변경`·`제거` 메뉴를 연다. 목록이 비어 있으면 "우클릭하여 연결기 추가" 안내 문구를 표시한다.
- 연결기를 추가할 때 식별자를 정하고, 연결기 부품은 선택하거나 나중에 선택할 수 있다.
- 부품이 없는 연결기도 신호표를 작성할 수 있다. 이때 핀 번호는 입력할 수 없으므로 모든 신호는 미할당 상태이다.
- 사이드바에서 연결기를 선택하면 메인 화면에 해당 연결기의 핀맵과 신호표를 표시한다.
- 각 연결기는 독립적인 신호와 핀 할당을 갖는다. 같은 연결기 부품을 사용하는 연결기라도 서로 영향을 주지 않는다.
- 연결기를 제거해도 연결기 부품 데이터베이스의 원본 부품은 유지한다.

### 3.2 프로젝트 파일과 저장
- 프로젝트 파일은 JSON 형식이며 확장자는 `.jnc`이다. 최상위에 `schema_version`을 둔다.
- 프로젝트 파일에는 신호유형 목록, 사용한 연결기 부품의 사본(UUID별 1개), 연결기(식별자, 부품 UUID, 좌우 반전 상태, 신호와 할당)를 저장한다. 다른 컴퓨터에 해당 부품이 없어도 핀 배치를 재현할 수 있어야 한다.
- 새로 만들기, 열기, 저장, 다른 이름으로 저장, 최근 파일 목록을 제공한다.
- 변경사항이 있는 상태에서 프로그램 종료, 새로 만들기, 다른 프로젝트 열기를 하면 저장 여부를 묻는다. 메인 화면과 연결기 부품 편집기 사이를 전환할 때는 묻지 않는다.
- 신호표에 미완료 입력이 있는 경우의 저장·전환 처리는 제3.6.1절을 따른다. 프로젝트 변경사항의 저장 여부 확인과는 별도로 입력 중인 값을 보호한다.
- 신호 중복이 남아 있어도 저장할 수 있다. 다시 열 때도 신호와 할당 상태를 유지하고 중복을 표시한다.
- 손상된 파일이나 상위 `schema_version` 파일은 오류 메시지를 표시하고 열지 않는다.
- 추후 전연결(`jeonnect`)과의 연동은 제6.2절의 향후 고려사항으로 둔다.

### 3.3 연결기 부품의 식별과 동기화
- 연결기 부품은 UUID로 식별한다. 부품명은 표시용이며 수정할 수 있다.
- 연결기 부품 데이터베이스 안에서 부품명은 대소문자 구분 없이 중복될 수 없다.
- 프로젝트는 사용하는 부품의 사본을 가지며 연결기는 부품 UUID로 사본을 참조한다.
- **연결기 부품 편집기에서 변경한 부품**: 편집기에서 메인 화면으로 전환하거나 편집기 화면에서 프로그램을 종료할 때 연결기 부품 데이터베이스를 자동 저장하고, 현재 열린 프로젝트에서 같은 UUID를 사용하는 연결기에 자동 반영한다.
  - 핀 이동·추가 등 할당이 유지되는 변경은 상태바에 알린다.
  - 핀이 삭제되어 할당이 해제되는 경우에는 영향받는 연결기와 신호를 확인 창으로 보여준다. 취소하면 저장·반영·전환(또는 종료)을 하지 않고 편집기에 남는다.
- **같은 UUID 부품의 정의 변경 규칙**: 부품 교체로 보지 않는다. 핀 위치가 바뀌거나 핀이 추가되어도 기존 할당은 유지한다. 삭제된 핀에 할당되었던 신호만 할당이 해제된다(제3.6절 행 규칙 적용). 핀 번호 변경은 기존 핀 삭제와 새 핀 추가로 취급한다.
- **다른 프로젝트를 열 때**: 프로젝트의 부품 사본이 연결기 부품 데이터베이스의 같은 UUID 부품과 다르면 자동으로 바꾸지 않고 알린다. 사용자가 "갱신"을 선택한 경우에만 위 규칙대로 반영한다.
- 연결기 부품 데이터베이스에서 부품을 삭제하면 프로젝트의 사본은 연결이 끊긴 상태로 유지되며 계속 사용할 수 있다.

### 3.4 핀맵 표시
- 연결기의 물리적 핀 위치와 핀 번호를 표시하며, **충분히 확대하면 각 핀에 할당된 신호명도 함께 표시**한다. 긴 신호명은 줄임표로 줄이고 툴팁으로 전체를 보여준다.
- 확대·축소할 때 **핀과 외곽선의 선 굵기는 확대 비율에 비례하지 않고 화면 기준 일정한 굵기를 유지**한다.
- 핀 색상은 다음 순서로 정한다.
  1. 신호의 개별 색상
  2. 신호유형의 색상
  3. 할당되었지만 두 색상이 모두 "없음"이면 흰색 채움과 검정 글자
- 미할당 핀은 할당 핀과 구분되도록 연회색으로 표시한다.
- 여러 신호가 할당된 핀(신호 중복)은 핀 가운데를 붉은 계열로 칠하고 빗금 또는 `!` 표시를 함께 해 붉은 신호유형 색상과 구분한다. 신호명 대신 `"신호 중복"`으로 표시하고, 마우스를 올리면 충돌한 신호 목록을 툴팁으로 보여준다.
- 핀을 선택하면 **선택한 핀만 외곽선을 굵게** 표시한다. 같은 신호가 할당된 다른 핀은 원래 외곽선 굵기를 유지한다.
- 선택한 핀에 신호가 할당되어 있으면 **선택한 핀과 동일한 신호가 할당된 모든 핀의 외곽선 바깥 주변 영역**(인접 핀과의 중간 정도 영역)을 칠한다. 같은 신호유형은 핀 채움 색상으로 이미 구분되므로 주변 영역은 동일 신호를 보여주는 용도로만 사용한다.
  - 주변 영역 색상은 핀 채움 색상(신호 색상 → 신호유형 색상)을 연하게(투명도 조정) 사용하고, 두 색상이 모두 "없음"이면 회색을 사용한다.
  - 인접 핀의 주변 영역이 겹쳐도 겹친 부분이 진해지지 않고 같은 색으로 보이게 한다.
  - 축소로 핀 사이 여유 공간이 적어도 주변 영역을 생략하지 않는다. 미할당 핀을 선택하면 주변 영역을 표시하지 않는다.
- 부품이 없는 연결기는 핀맵에 "연결기 부품이 선택되지 않았습니다"를 표시한다.

### 3.5 좌우 반전
- 연결기 부품은 기준 메이팅면(정면) 한 방향으로 관리하며, 반전용 부품을 별도로 만들지 않는다.
- 연결기별로 좌우 반전 옵션을 두고 프로젝트에 저장한다. 같은 부품을 쓰는 연결기라도 반전 상태가 다를 수 있다.
- 반전은 외곽 중심을 지나는 세로축 기준으로 표시 위치에만 적용한다. 핀 번호·신호명 글자는 뒤집지 않으며, 부품 원본 좌표와 신호 할당은 바꾸지 않는다.
- 핀맵 헤더 바에 현재 보는 면을 `정면`(기본) 또는 `배면`(반전)으로 표시한다. 반전 변경은 할당을 해제하지 않는다.

### 3.6 신호와 신호표 행
- 신호표는 선택한 연결기의 신호를 행으로 표시한다. 열은 핀 번호, 신호명, 신호유형, 색상이다.
- **행 규칙**: 신호는 할당된 핀 수만큼 행을 가지며(핀 하나에 행 하나), 할당된 핀이 없는 신호는 미할당 행 하나를 가진다. 모든 편집 결과는 이 규칙을 따른다.
  - 여러 핀에 할당된 신호의 한 핀을 해제하면 그 행은 사라진다.
  - 신호의 마지막 핀이 해제되면 미할당 행 하나로 남는다.
  - 미할당 신호는 신호명으로 관리되므로 같은 신호의 미할당 행은 하나로 합쳐진다.
- **신호명 규칙**
  - 신호명은 연결기 안에서 신호의 키이며 속성이 아니다.
  - 영문 대문자, 숫자, 언더스코어(`_`)만 사용할 수 있으며 영문자로 시작한다. 공백·한글·그 밖의 특수문자(`+`, `-`, `/` 등)는 사용할 수 없다.
  - 대소문자를 구분하지 않으며 소문자로 입력해도 대문자로 변환해 관리한다.
  - 빈 이름은 허용하지 않으며 길이는 32자 이하이다.
  - 차동 신호는 `_P`, `_N` 접미사로 구분한다.
- **신호명 편집**: 한 행의 신호명을 바꾸면 그 행만 다른 신호가 된다. 예를 들어 GND가 할당된 핀 3개 중 한 행을 GROUND로 바꾸어도 다른 두 행은 GND로 유지된다.
  - 바꾼 이름의 신호가 이미 있으면 그 행은 해당 신호의 속성을 따른다.
  - 처음 쓰는 이름이면 이전 신호의 신호유형·색상을 복사한 새 신호가 생성된다. 이전 신호가 다른 행에도 쓰이면 그 신호의 속성은 그대로 유지된다.
  - 행이 하나도 남지 않은 이전 신호는 사라진다.
- **속성 편집**: 신호유형과 색상을 바꾸면 같은 신호의 모든 행과 핀에 반영한다. 색상 선택에는 "없음" 항목이 있다.
- **색상 열 표시**: 칸 배경을 핀 채움 색으로 칠하고 글자는 `개별`(신호 개별 색상), `유형`(신호유형 색상), `없음`으로 짧게 표시한다. 색상 코드는 툴팁으로 보여 준다. 입력 행의 색상 버튼도 같은 방식으로 표시한다.
- **입력용 빈 행**: 표의 마지막에는 항상 입력용 행 하나를 둔다. 핀 번호부터 입력할 수 있고, 행 끝의 `추가` 버튼으로 확정한다(제3.6.1절). 신호명 입력만으로 즉시 생성하지 않는다.
- **행 삭제**: 실수 방지를 위해 `Delete` 키는 사용하지 않는다. 행 헤더(제일 좌측 핸들 영역)를 선택한 뒤 우클릭 컨텍스트 메뉴로 삭제한다. 다른 행에도 사용된 신호는 선택한 행만 지우고, 그 행만 가진 신호는 신호도 함께 삭제한다.
- **정렬**
  - 핀 번호·신호명·신호유형 열 헤더를 누르면 해당 열 기준 오름차순·내림차순으로 정렬한다.
  - 처음 열 때는 핀 번호 오름차순이며 정렬 상태는 저장하지 않는다.
  - 신호명·신호유형 정렬에서 값이 같은 행은 핀 번호 순서로 놓는다. 같은 핀에 중복된 행끼리는 신호명 오름차순으로 놓는다.
  - 미할당 행은 항상 할당 행 뒤에 두고 미할당 행끼리 정렬한다. 입력용 빈 행은 항상 맨 끝이다.
  - 핀맵·신호표에서 할당이나 해제가 확정되면 현재 정렬 열과 방향을 유지해 즉시 재정렬한다. 상세 동작은 제3.6.2절을 따른다.
- 신호와 신호표는 연결기별로 관리한다. 프로젝트 전체 공통 신호는 향후 고려사항이다.
- 한쪽(핀맵 또는 신호표)에서 변경된 내용은 즉시 다른 쪽에 반영된다.

#### 3.6.1 새 신호 입력 행 개선 (구현 완료)

신호 입력값은 확정 전까지 화면의 입력 상태로 유지하고, `추가`할 때 검증한 값 전체를 편집 명령 하나로 프로젝트에 반영한다.

| 핀 번호 | 신호명 | 신호유형 | 색상 | 동작 |
| --- | --- | --- | --- | --- |
| 직접 입력·선택 | 직접 입력·기존 신호 선택 | 직접 입력·선택 | 선택·없음 | `추가` · `초기화` |

- 마지막 행을 **입력 중인 행**으로 관리하여 어느 열부터든 입력할 수 있게 한다. 핀 번호 → 신호명 → 신호유형 순서로 입력해도 된다. 부품이 없는 연결기에서는 기존 규칙대로 핀 번호 입력을 비활성화한다.
- 신호명이 없는 상태에서도 핀 번호·신호유형·색상을 먼저 입력할 수 있다. 다만 신호명 없이 `추가`를 확정할 수는 없다.
- 신호명 입력이나 셀 이동만으로 신호를 생성하지 않는다. `Enter`, `추가` 버튼 또는 `Ctrl+Enter`로 확정할 때 입력값을 함께 검증하고 신호 생성·재사용과 핀 할당을 한 번에 반영한다.
- 신호명은 필수이며 핀 번호·신호유형·색상은 선택이다. 핀 번호가 없으면 미할당 신호로 추가한다. 새 신호의 신호유형·색상이 비어 있으면 각각 `없음`으로 처리한다.
- 해당 연결기의 기존 신호를 선택하면 신호유형과 색상을 가져와 표시하고, 입력 중인 행에서는 두 속성을 읽기 전용으로 둔다. 기존 신호를 재사용하는 과정에서 공유 속성을 바꾸지 않으며, 속성 변경은 추가 후 기존 행 편집으로 수행한다.
- 새 신호유형을 입력하더라도 `추가` 확정 전에는 프로젝트의 신호유형 목록에 생성하지 않는다. 미완료 입력은 실제 신호 목록·핀 할당·프로젝트 저장 내용·중복 경고 수에 반영하지 않는다.
- 입력 중인 행은 정렬과 관계없이 표의 맨 아래에 유지한다. 기존 행은 지금처럼 즉시 편집·반영하며 `추가` 버튼을 요구하지 않는다.
- `추가`에 성공하면 기존의 신호·행 규칙에 따라 반영하고, 맨 아래에 새 빈 입력 행을 준비한다. `초기화`는 현재 입력 중인 값만 비운다.
- 유효하지 않은 신호명이나 부품에 없는 핀 번호는 해당 칸에 안내하고 입력값을 유지한다. 일부 값만 프로젝트에 반영하지 않는다. 중복 핀 할당은 기존 규칙대로 추가를 허용하고, 확정 후 붉은 배경과 중복 경고 수에 반영한다.
- `Tab`으로 입력 칸 사이를 이동한다. 입력 칸의 목록이 닫혀 있을 때 `Enter`를 누르면 입력 행을 추가한다. 단, 핀 번호 칸에서 신호명이 비어 있으면 오류 없이 신호명 칸으로 이동한다. 목록이 펼쳐져 있을 때 `Enter`는 항목 선택에만 쓴다. 추가에 성공하면 커서는 입력 행의 핀 번호 칸으로 돌아간다.
- 입력 중인 값이 남은 상태에서 저장·다른 이름으로 저장, 다른 연결기 선택, 부품 교체, 편집기 전환, 새 프로젝트·다른 프로젝트 열기 또는 프로그램 종료를 요청하면 먼저 `추가`·`버리기`·`취소`로 처리한다. `추가`가 실패하면 입력을 유지하고 요청한 작업을 진행하지 않는다. `버리기`는 입력 중인 값만 버리고, `취소`는 입력과 현재 화면을 유지한다. 이미 확정된 프로젝트 변경사항의 저장 확인은 기존 규칙을 따른다.

#### 3.6.2 할당 변경 후 즉시 정렬 (구현 완료)

- **수정한 문제:** 핀맵에서 신호를 해제할 때 표 내용만 갱신되어 미할당 행이 기존 위치에 남았다. 표 갱신 시 현재 정렬을 재적용하고 행의 고유 식별자로 선택을 복원하도록 수정했다.
- 핀맵과 신호표 어느 쪽에서 변경하든, 할당·해제 확정 후 행 규칙을 적용하고 사용자가 선택한 정렬 열과 오름차순·내림차순을 유지해 즉시 재정렬한다. 열 제목을 다시 누르거나 연결기를 다시 선택할 필요가 없어야 한다.
- 신호의 마지막 핀 할당을 해제하면 미할당 행 하나로 남기고, 할당된 모든 행 아래의 미할당 영역으로 즉시 이동한다. 미할당 행 사이에도 기존 정렬 규칙을 적용한다.
- 다른 핀에도 할당된 신호의 한 핀만 해제하면 그 핀의 행을 제거하며, 별도의 미할당 행을 만들지 않는다. 핀맵에서 기존 신호를 다른 신호로 교체해 밀려난 신호에도 같은 규칙을 적용한다.
- 재정렬 대상은 확정된 신호 행이다. 제3.6.1절의 입력 중인 행은 값이 사라지거나 중간으로 이동하지 않도록 맨 아래에 유지한다.
- 행 위치가 바뀌어도 선택 연동이 다른 핀이나 신호를 가리키지 않아야 한다. 해제한 핀이 미할당이 되면 신호표 선택은 제3.8절에 따라 해제한다.
- **검증 기준:** 핀맵·신호표 양쪽의 할당·해제, 마지막 핀 해제와 여러 핀 중 일부 해제, 신호 교체, 각 정렬 열·방향, 입력 중인 행 유지와 선택 연동을 확인한다.

### 3.7 핀맵에서 신호 할당·해제
- 핀을 우클릭하면 컨텍스트 메뉴로 해당 연결기의 기존 신호(할당·미할당 신호 모두)를 골라 할당하거나 할당을 해제한다. 핀맵에서는 새 신호를 만들지 않는다.
- 컨텍스트 메뉴는 스크롤할 수 있으며, 키보드로 글자를 입력하면 그 글자로 시작하는 첫 번째 항목으로 이동한다.
- 이미 신호가 있는 핀(신호 중복 핀 포함)에 다른 신호를 할당하면 기존 신호를 모두 교체한다. 밀려난 신호 중 그 핀에만 할당되었던 신호는 미할당 신호가 되고, 다른 핀에도 할당된 신호는 그 행만 사라진다.
- 할당을 해제하면 그 핀의 신호를 모두 해제하며 각 신호에 제3.6절 행 규칙을 적용한다.
- 핀맵에서는 신호 중복이 생기지 않는다. 신호 중복은 신호표에서 핀 번호를 입력할 때만 생긴다.

### 3.8 선택 동기화 (하이라이트)
- 선택은 단일 선택만 지원한다.
- **핀맵 → 신호표**: 핀을 선택하면 신호표에서 **그 핀에 해당하는 행만** 선택한다. 동일 신호의 다른 핀 행은 함께 선택하지 않는다.
- **신호표 → 핀맵**: 할당된 행을 선택하면 해당 핀이 선택되고 제3.4절에 따라 선택한 핀의 굵은 외곽선과 동일 신호 핀들의 주변 영역이 표시된다. 미할당 행을 선택하면 핀맵에는 강조 표시를 하지 않는다.
- 신호 중복 핀을 선택하면 현재 정렬 순서에서 그 핀이 할당된 첫 번째 행을 선택한다.
- 미할당 핀을 선택하면 핀만 선택되고 신호표 선택은 해제된다. 핀맵의 빈 곳을 클릭하면 선택을 해제한다.

### 3.9 핀 번호 입력과 중복 검증
- 신호표의 핀 번호는 **입력 가능한 콤보 박스**로 편집한다. 부품이 없는 연결기에서는 입력할 수 없다.
- 핀 번호는 숫자뿐 아니라 문자가 포함된 번호(예: `A`, `a`, `A1`)도 지원하며 **대소문자를 구분**한다. 공백(앞뒤·중간)은 허용하지 않는다.
- 해당 연결기 부품에 존재하는 핀 번호만 사용할 수 있다. 직접 입력하거나 드롭다운에서 선택하며, 부품에 없는 핀 번호를 입력하면 거부한다.
- 드롭다운은 첫 항목에 "미할당"을 두고, 핀 번호를 자연 정렬(대소문자는 ASCII 순서, 예: `A2` < `A10`, `A` < `a`)로 표시한다. "미할당"을 선택하면 할당 해제와 같다.
- 미할당 핀 번호 칸은 표와 편집 상자 모두 **빈칸**으로 두고, 편집 상자가 빈칸일 때만 회색 안내 글자 "미할당"을 보인다. 빈칸으로 확정하면 미할당이며, 드롭다운에서 "미할당"을 고르면 칸이 빈칸이 된다. 신호유형 칸의 "없음"도 같은 방식으로 표시한다.
- 같은 연결기 안에서 여러 행에 같은 핀 번호를 할당하면 신호 중복으로 판단해 해당 행 모두의 핀 번호 셀을 붉은 계열 배경으로 표시하고 핀맵에도 표시한다. 중복이 해소되면 정상 표시로 돌아온다.
- 미할당은 중복으로 판단하지 않는다. 서로 다른 연결기의 같은 핀 번호도 중복이 아니다.

### 3.10 신호유형
- 신호유형 목록은 프로젝트에 저장한다. 새 프로젝트는 기본 신호유형 목록으로 시작한다.
- 신호표의 신호유형은 **입력 가능한 콤보 박스**로 편집한다. 목록에 없는 이름을 입력하면 새 신호유형이 추가된다.
- 신호유형 관리 창에서 신호유형을 표로 보여주고 추가·수정·삭제할 수 있다.
  - 이름을 바꾸면 그 신호유형을 사용하던 신호가 바뀐 이름을 따라간다.
  - 삭제하면 그 신호유형을 사용하던 신호는 신호유형 없음이 된다.
- **신호표 바로가기**: 신호표의 신호유형 칸을 우클릭하면 그 유형의 `색상 변경`(프로젝트에서 그 유형을 쓰는 신호 수 표시)·`색상 없음`·`이름 변경` 메뉴를 쓴다. 그 밖의 칸 우클릭은 신호 개별 색상 메뉴이다. 입력 중인 행에는 메뉴가 없고, 신호유형이 없는 행은 비활성 안내만 보인다.
  - 유형 색상을 바꿀 때 개별 색상을 가진 신호가 있으면 그 신호들은 개별 색상으로 표시된다고 상태 표시줄로 알린다.
  - 입력 중인 행이 바꾸기 전 유형 이름을 쓰고 있으면 새 이름으로 따라 바꾼다.
  - 삭제, 쓰지 않는 유형 정리, 사용 전 색상 지정, 전체 유형·색상 확인은 신호유형 관리 창에서 한다.
- 신호유형이 없는 신호도 허용한다.
- 이름 규칙: 한글을 허용하는 것 외에는 신호명과 같다. 영문 대문자·한글·숫자·언더스코어만 사용하고 영문자 또는 한글로 시작하며, 공백은 허용하지 않고 32자 이하이다. 대소문자를 구분하지 않으며 영문은 대문자로 변환해 표시한다.
- 신호유형 색상은 선택 사항이며 새로 만들 때 "없음"이다.

### 3.11 연결기 부품 교체
- 연결기의 부품을 UUID가 다른 부품으로 바꾸는 것을 교체라 한다. 같은 UUID 부품의 정의 변경은 제3.3절을 따른다.
- 교체 전 "모든 신호 할당이 해제됩니다." 확인 창을 띄운다.
- 교체해도 연결기 식별자와 신호(신호명, 신호유형, 색상)는 유지하고, 할당은 **모두 해제**한다. 새 부품에 같은 핀 번호가 있어도 자동으로 할당하지 않는다. 각 신호는 미할당 행 하나로 합쳐진다.
- 핀맵은 새 부품의 외형과 핀 배치로 바뀌고, 핀 번호 드롭다운은 새 부품의 핀 목록을 표시한다.

### 3.12 상태 표시
- 상태바에는 프로젝트 전체의 신호 중복 경고 수를 표시한다. 중복된 핀 하나를 경고 한 건으로 집계하며 중복 행 개수와 구분한다.
- 경고 수에는 신호 중복만 포함한다. 미할당 신호, 부품이 없는 연결기 등 설계 중인 상태와 부품 변경 반영 알림은 정보 수준으로 표시한다.

## 4. 화면 구성 및 조작 방식 (UI / UX)

### 4.1 창 구성
- 화면은 왼쪽 **사이드바**와 **메인 화면**(좌측 핀맵, 우측 신호표)으로 구성한다.
- 핀맵은 고정 영역이고, 사이드바와 신호표는 크기 조정과 **도킹(Docking)·플로팅(Floating)**이 가능하다.
- 창 배치와 신호표 열 너비는 앱 설정에 저장해 다음 실행 때 복원하며, "배치 초기화" 메뉴는 둘 다 기본값으로 되돌린다.
- 신호표의 모든 열은 경계선을 끌어 너비를 조정한다(경계선 더블클릭 시 내용에 맞춤). 열 너비는 창 너비에 맞춰 늘리지 않으며(신호명 기본 `180`), 남는 공간은 오른쪽 빈 공간으로 둔다.
- 핀맵과 신호표 사이 경계선을 이동해 핀맵을 좁히고 신호표에 공간을 더 배분할 수 있다. 신호표의 열이 늘어나도 핀맵의 최소 너비를 함께 늘리지 않으며, 신호표는 필요하면 가로로 스크롤한다.
- 핀맵 상단은 연결기 제목·보는 면, 부품 선택, 반전·확대·축소·전체 보기의 세 줄로 구성해 한 줄 도구 모음이 최소 너비를 강제하지 않게 한다. 긴 제목은 줄임표와 툴팁으로 표시하며 부품 선택 상자의 너비도 패널에 맞춰 줄인다. 좁은 상태에서도 모든 조작에 접근할 수 있다.

| 영역 | 표시 내용과 기능 |
| --- | --- |
| 사이드바 | 연결기 식별자 목록, 연결기 추가·제거·식별자 변경, 작업할 연결기 선택, 신호 중복 경고 아이콘 |
| 메인 화면 좌측 (핀맵) | 상단 헤더 바(연결기 정보, 부품 선택·변경, 좌우 반전과 `정면`/`배면` 표시, 전체 보기)와 핀맵 캔버스 |
| 메인 화면 우측 (신호표) | 신호 목록, 핀 번호 할당, 신호명·신호유형·색상 편집, 열 헤더 정렬, 행 헤더 우클릭 삭제 |

- 연결기를 선택하면 핀맵과 신호표가 함께 해당 연결기로 전환된다.
- 부품이 없는 연결기는 헤더 바의 부품 변경 버튼이 "부품 선택"으로 동작하고, 좌우 반전과 전체 보기는 비활성화한다.

### 4.2 주요 작업 흐름
1. 사이드바에서 연결기 추가를 선택한다.
2. 연결기 식별자를 정하고 연결기 부품을 선택한다(나중에 선택해도 된다).
3. 추가된 연결기를 선택하면 메인 화면 좌측에 핀맵, 우측에 신호표가 나타난다.
4. 신호표의 마지막 입력 행에서 핀 번호·신호명·신호유형·색상을 입력한 뒤 `추가`로 확정한다(제3.6.1절). 또는 핀맵에서 핀을 우클릭해 기존 신호를 할당한다. 신호 중복은 신호표의 붉은 배경과 핀맵의 `"신호 중복"` 핀으로 확인한다.
5. 핀맵 헤더 바에서 좌우 반전을 전환하거나 부품을 교체한다. 교체하면 신호는 유지되고 할당은 모두 해제된다.

### 4.3 핀맵 조작 (CAD 스타일 내비게이션)
- **확대·축소**: 마우스 휠(커서 위치 기준)과 키보드 단축키.
- **화면 이동**: 휠 버튼 드래그, 스페이스바+왼쪽 드래그, 키보드 방향키. 빈 곳 왼쪽 드래그에는 기능을 두지 않는다. 핀 위 우클릭은 신호 할당 컨텍스트 메뉴에 사용한다.
- **전체 보기**: 헤더 바의 전체 보기 버튼 또는 단축키로 연결기 전체가 화면에 들어오도록 배율과 위치를 초기화한다.

### 4.4 연결기 부품 데이터베이스와 편집기
- 전연결기는 자체 연결기 부품 데이터베이스를 사용자 데이터 폴더(Qt `QStandardPaths`)에 JSON으로 저장한다.
- 연결기 부품 편집기를 선택하면 메인 화면 전체를 편집 화면으로 전환한다. 별도 실행 프로그램으로 분리하지 않는다. 저장과 반영은 제3.3절을 따른다.
- 부품 목록에서 선택한 부품만 가져오기·내보내기 할 수 있다. 프로젝트의 신호와 할당은 내보내기에 포함하지 않는다.
- 가져올 때 같은 UUID의 부품이 있으면 경고를 띄워 **덮어쓸지, 이름을 바꾸어 추가할지** 묻는다. 이름을 바꾸어 추가하면 새 UUID를 발급한다. UUID는 다르지만 부품명이 같으면 이름을 바꾸어야 추가할 수 있다.
- 편집기는 다음 기능을 제공한다.
  - 부품 정보(부품명, 설명) 편집
  - 핀 번호·좌표 편집, 핀 추가·이동·삭제
  - 부품 단위의 핀 모양·크기 설정
  - 바둑판·원형 **자동 배치**: 행 오프셋을 지원해 D-SUB·Micro-D 같은 엇갈린 배열도 만든다. 바둑판 기본 간격은 기본 부품 기준인 가로 `40`, 세로 `48`이다.
  - `다각형 외곽`·`원형 외곽` **연결기 외곽 생성**: 누르면 기존 외곽을 대체해 바로 생성한다. 핀이 있으면 기본 부품과 같은 여백(핀 중심 기준 좌우 `30`, 위 `22`, 아래 `32`, 원형은 가장 바깥 핀에서 `30`)으로 만들고, 핀이 없으면 부품 영역 안쪽 `12` 여백으로 만든다. 다각형은 사각형으로 시작해 꼭짓점 이동, 변 더블클릭으로 꼭짓점 추가, 꼭짓점 우클릭으로 삭제하고, 가운데 핸들로 전체를 옮긴다. 원형은 중심 핸들로 이동하고 반지름 핸들로 크기를 조정한다. 꼭짓점·반지름 핸들은 정사각형, 가운데·중심 핸들은 원에 십자선이 겹친 모양으로 구분해 표시한다. 가운데 핸들이 핀과 겹치면 핀 선택을 우선한다.
- **핀 선택과 이동**(선택/이동 모드):
  - 빈 곳을 왼쪽 드래그하면 점선 사각형이 그려지고, 놓을 때 **핀 중심이 사각형 안에 있는** 핀을 선택한다. 끌지 않고 빈 곳을 클릭하거나 `Esc`를 누르면 선택을 해제한다.
  - `Ctrl`+클릭은 핀 하나를 선택에 넣거나 빼고, `Ctrl`+영역 드래그는 기존 선택에 추가한다.
  - 선택된 핀 하나를 잡고 끌면 선택된 핀 전체가 같은 거리만큼 함께 이동한다.
  - 캔버스 선택과 핀 목록 표의 행 선택(여러 행 가능)은 서로 맞춘다.
  - 화면 이동은 휠 버튼 드래그와 스페이스바+왼쪽 드래그로 한다. 빈 곳 왼쪽 드래그는 영역 선택에 쓴다.
- 새 부품은 핀과 외곽 없이 크기 `400×300`, 핀 지름 `16`으로 시작한다. 별도 저장 단계 없이 편집할 때마다 연결기 부품 데이터베이스에 저장된다.
- **부품 영역 자동 조정**: 부품 영역(너비·높이)은 외곽선과 핀(반지름 포함)의 가장 바깥에서 `12` 여유를 두고 **현재 중심 기준 대칭**으로 맞춘다. 영역이 왼쪽·위로 늘거나 줄면 좌표를 함께 옮겨 중심에 대한 상대 위치를 유지하므로 중심 원점의 그리드가 밀리지 않는다. 드래그 중이 아니라 편집이 끝났을 때(마우스를 놓았을 때) 조정하며, 핀과 외곽이 모두 없으면 영역을 그대로 둔다. 가로·세로 크기 입력란은 두지 않는다.
- 핀 번호는 부품 안에서 중복될 수 없으며 제3.9절의 문자 규칙을 따른다.
- 기존 전연결 편집기의 통일성 없는 UI를 따르지 않고, 상용 CAD 프로그램의 조작 방식을 참고해 외곽 그리기·핀 추가·자동 배치의 UI 통일성과 조작성을 개선한다.

### 4.5 그리드와 스냅
- 편집 화면의 그리드 표시와 스냅은 **처음부터 켜진 상태**로 제공하며, 사용자가 간격과 켜짐 상태를 조정할 수 있다.
- **그리드에 맞지 않는 좌표의 핀도 허용**한다. 단, 그리드와 스냅이 켜져 있을 때 핀을 마우스로 이동하면 그리드에 맞게 좌표가 변경(스냅)된다. 여러 핀을 함께 옮길 때는 마우스로 잡은 핀만 그리드에 맞추고 나머지 핀은 같은 거리만큼 옮겨 핀 사이 간격을 유지한다.
- 다각형 외곽은 꼭짓점과 가운데 이동 핸들을, 원형 외곽은 중심과 반지름을 기준으로 편집·스냅한다. 원형의 곡선 전체를 격자점으로 바꾸거나 다각형으로 변환하지 않는다.
- **스냅에 맞추기**: 도구 막대의 버튼으로 부품의 모든 핀과 외곽(다각형 꼭짓점, 원형 중심·반지름)을 현재 그리드 간격의 가장 가까운 격자점으로 한 번에 옮긴다. 두 핀이 같은 격자점에 모이면 옮기지 않고 알린다. 편집이 바로 저장되므로 실행 전에 이동할 핀·외곽 점 수를 보여 주고 확인을 받는다.
- 좌표는 논리적 표시용이며 제작 치수로 사용하지 않는다.

### 4.6 기본 제공 연결기 부품
- 처음 실행할 때 연결기 부품 데이터베이스에 전연결의 기본 연결기 구성을 참고한 다음 27종을 넣는다.

| 종류 | 구성 | 개수 |
| --- | --- | --- |
| D-SUB SD | 9·15·25·37·50핀 | 5종 |
| D-SUB HD | 15·26·44·62·78핀 | 5종 |
| D38999 Series IV | B·C·D·E·F·G·H·J 셸의 `-35` 배열 | 8종 |
| Micro-D MDM | 9·15·21·25·31·37·51·69·100핀 | 9종 |

- 기본 부품 도식은 실제 치수가 아닌 논리 도식이며, 부품마다 핀 크기와 빈 공간의 비율이 같도록 다음 규칙으로 만든다.
  - 가장 가까운 핀 중심 거리 `40`, 핀 지름 `16`. D-SUB·Micro-D의 행 간격은 원래 배열 비율을 따라 SD `48`, HD `44.4`, Micro-D `62.2`로 둔다. D38999는 접점 좌표 데이터를 가장 가까운 접점 거리가 `40`이 되도록 확대·축소한다.
  - 외곽선은 핀 배열 경계에서 일정한 여백을 둔다. 핀 중심 기준 좌우 `30`, 위 `22`, 아래 `32`(핀 아래 신호명 자리), 원형은 가장 바깥 핀에서 `30`. 사다리꼴 아래 변은 좌우 `18`씩 들여 쓰고, 외곽선과 부품 경계 사이는 `12`이다.
  - 부품의 겉보기 크기는 핀 수와 배열에 따라 달라진다. 10자 신호명끼리 약간 겹치는 것은 허용한다.
- 기본 부품은 고정 UUID를 가지며 다른 부품처럼 수정·삭제할 수 있다. "기본 부품 복원" 기능으로 기본 27종을 원래 정의로 되돌리거나 다시 추가한다.
- 참고 근거는 전연결 저장소의 `docs/default-connector-library.md`, `packages/jeonnect_core/connector/defaults.py`와 D38999 접점 좌표 데이터이다. 그리드·스냅은 `docs/connector-library.md`와 `apps/jeonnect/connector_editor.py`를 참고한다.
- 참고 원본 저장소는 수정하지 않는다.

## 5. 개발·배포 방향 및 참고 저장소

### 5.1 개발 환경과 구조
- **개발 환경과 실행 환경 모두 Windows와 Linux**를 지원한다.
- Python 3.13+과 PySide6를 사용한다. PySide6는 최신 안정판(`PySide6==6.12.0`)으로 고정한다.
- 테스트는 `pytest`와 `pytest-qt`를 사용한다.
- 소스는 `src/jeonnector/` 아래에 데이터 모델(`model.py`), 명령 계층(`commands.py`), 저장(`storage.py`), 화면(`ui/`)을 분리한다.
- 모든 편집은 하나의 편집 계층(명령 객체)을 거치도록 구성해, 추후 실행 취소·다시 실행을 도입할 수 있게 한다.

### 5.2 배포
- 각 운영체제에서 Python을 별도로 설치하지 않아도 실행할 수 있도록 PyInstaller로 패키징한다. Windows용은 Windows에서, Linux용은 Linux에서 각각 빌드·검증한다.
- 우선 폴더 형태(onedir)로 배포하고, 단일 실행 파일(onefile)은 배포 대상(내부용/외부용)과 PySide6 라이선스(LGPL) 조건을 확인한 뒤 결정한다.
- 한글 표시는 시스템 글꼴을 사용한다.

### 5.3 참고 저장소와 작업 공유
- 개발 대상은 `hankjeon/jeonnector`이다.
- `hankjeon/jeonnect`는 코드·문서·구조를 읽는 **참고 전용** 저장소이다. 수정·커밋·푸시하지 않으며, 그 저장소의 기술 구성이나 데이터 모델을 임의로 도입하지 않는다.
- 클라우드와 로컬 작업은 GitHub를 통해 커밋·푸시·풀하여 공유한다. 작업 시작 전 원격 `main`을 확인하고, 완료된 변경과 인수인계 문서를 함께 관리한다.
- 커밋하지 않은 파일과 Git에서 제외한 파일은 이 방식으로 전달되지 않는다. Python 가상환경과 설치된 패키지는 각 작업 환경에서 별도로 준비한다.

### 6.2 향후 고려사항

- **프로젝트 전체 공통 신호 관리**: 현재는 연결기별 독립 신호만 관리한다.
- **실행 취소·다시 실행(Undo/Redo)**: 지원 여부와 범위는 추후 결정한다. 편집 계층(`CommandDispatcher`)은 제5.1절에 따라 구성 완료했다.
- **전연결(`jeonnect`) 연동**: 부품 라이브러리 가져오기, 프로젝트 내보내기 등 구체적인 연동 방식은 추후 결정한다.
- **단일 실행 파일 배포**: 배포 대상과 라이선스 조건 확인 후 결정한다.
- **한글 글꼴 포함 배포**: 시스템 글꼴이 부족한 환경이 확인되면 검토한다.

### 6.3 후속 구현을 완료한 개선사항

- **신호표의 입력 중인 행과 명시적 추가**(제3.6.1절): 컬럼 순서대로 자유롭게 입력하고 `추가`·`Ctrl+Enter`로 확정한다. 기존 신호 선택 시 속성 표시·읽기 전용 처리, 검증 실패 시 입력 유지, `초기화`, 미완료 입력의 저장·전환 보호와 키보드 이동을 구현했다.
- **할당 변경 후 신호표 즉시 정렬**(제3.6.2절): 핀맵·신호표의 할당·해제 후 현재 정렬을 다시 적용한다. 마지막 핀 해제 시 미할당 영역으로 즉시 이동하고, 여러 핀 중 일부 해제 시 해당 행만 제거한다. 입력 중인 행과 선택 연동도 유지한다.
- **핀맵 최소 너비 축소**(제4.1절): 상단을 세 줄로 구성하고 부품 선택 상자의 고정 최소 너비를 제거했다. 긴 연결기 제목은 줄임표와 툴팁으로 확인한다. Linux 오프스크린 검증 환경에서 핀맵 너비 228픽셀로 모든 조작을 사용할 수 있음을 확인했으며, 실제 최소 너비는 시스템 글꼴과 화면 배율에 따라 달라진다.
