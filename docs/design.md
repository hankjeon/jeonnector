# 전연결기(jeonnector) 요구사항 및 화면 설계

> 상태: **요구사항 정리, 기능 구현 예정**
>
> 사용자가 요청한 기능과 기존 설계는 아래에 정리한다. 기술·배포 방식과 세부 동작 중 추가 결정이 필요한 내용은 별도로 **검토 중**으로 표시한다. 이 문서는 요구사항 및 화면 설계 문서이며, 구현된 기능을 설명하는 사용 설명서는 추후 실제 화면을 기준으로 작성한다.

## 1. 프로젝트 개요 및 목적

연결기(Connector)에 신호(Signal)를 배치할 때는 인접 핀과의 간섭, 전원/접지 분포 등 **신호의 물리적 특성에 따른 공간적 배치**가 중요하다.

프로그램의 한글 이름은 **전연결기**, 저장소 이름은 `jeonnector`이다. 참고 프로그램 `jeonnect`의 한글 이름은 **전연결**이다.

전연결기는 다음 목적을 위해 개발한다.
- 연결기의 물리적 핀 배치(Layout)와 각 핀에 할당된 신호명을 직관적으로 시각화한다.
- 신호의 특성(카테고리)에 따라 핀 색상을 구분하여 물리적 배치의 적절성을 쉽게 파악하게 한다.
- 그래픽 핀맵 뷰와 표 형태의 신호 목록을 연동하여 조회와 편집을 빠르게 수행한다.

## 2. 핵심 기능 요구사항

### 2.1 프로젝트와 연결기 관리
- 하나의 프로젝트에 여러 연결기를 추가하거나 제거할 수 있다.
- 각 연결기는 프로젝트 안에서 중복되지 않는 식별자를 갖는다(예: `J1`, `J2`, `P1`).
- 왼쪽 프로젝트 사이드바에는 연결기를 식별자로 표시한다.
- 연결기를 추가할 때 식별자를 정하고, 연결기 부품 목록에서 사용할 부품을 선택한다.
- 연결기 항목의 신호표는 부품 지정과 독립적으로 작성할 수 있다. 부품을 아직 지정하지 않았더라도 해당 연결기의 신호를 작성·유지한다.
- 사이드바에서 연결기를 선택하면 메인 화면에 해당 연결기의 핀맵과 신호표를 표시한다.
- 각 연결기는 독립적인 신호 목록과 핀 할당을 갖는다. 같은 부품을 사용하는 연결기라도 신호 할당은 서로 영향을 주지 않는다.
- 프로젝트에 추가한 연결기를 제거해도 부품 목록의 원본 부품 정의는 유지한다.

### 2.2 부품 정의와 연결기별 신호 맵
- 부품 정의는 연결기의 외형, 물리적 핀 배치와 핀 번호를 제공한다.
- 프로젝트의 연결기는 선택한 부품과 연결기별 신호 맵을 갖는다.
- 신호표는 핀당 한 행으로 고정하지 않고, **신호를 기준으로 행을 관리**한다. 각 신호 행에 핀 번호를 할당할 수 있으며, 핀이 할당되지 않은 신호도 표에 유지한다.
- 프로젝트 파일에는 사용한 부품 정의를 함께 저장한다. 다른 컴퓨터에 해당 부품 데이터베이스가 없어도 프로젝트의 핀 배치를 재현할 수 있어야 한다.
- 부품 데이터베이스를 수정해도 기존 프로젝트에 포함된 부품 정의는 자동으로 변경하지 않는다. 사용자가 명시적으로 부품을 교체할 때 반영하며, 이 경우 제2.7절에 따라 핀 할당을 모두 해제한다.
- 실제 저장 형식은 JSON을 기본으로 사용하며, 추후 전연결(`jeonnect`)과의 연동을 고려한다.

### 2.3 연결기 핀맵 시각화
- 연결기의 물리적 핀 위치와 핀 번호(식별자)를 캔버스에 표시하며, **핀맵 뷰를 충분히 확대하면 각 핀에 할당된 신호명도 함께 표시**한다.
- 화면을 확대하거나 축소할 때 **핀이나 연결기 외곽선의 선 굵기는 확대 비율에 비례하여 굵어지지 않고 화면 기준 일정한 굵기를 유지**한다.
- 평상시 각 핀은 할당된 신호의 개별 색상을 우선 사용하고, 개별 색상이 없으면 신호 카테고리(신호유형)의 색상을 사용한다. 미할당 핀은 기본 색상으로 표시한다.
- 여러 신호가 중복 할당된 핀은 핀 가운데를 붉은 계열 색상으로 칠하고 신호명 대신 `"신호 중복"`이라고 표시해 오류가 있는 핀으로 보이도록 한다.
- 핀을 선택하면 **선택한 핀과 동일한 신호가 할당된 모든 핀의 외곽선을 굵게** 표시한다. 또한 **선택한 신호와 같은 카테고리(신호유형)의 핀들은 핀 외곽선 바깥 주변 영역**(주변 인접 핀과의 중간 정도 영역, 사각형 또는 원형)을 카테고리 색상보다 **연한 색(투명도/알파값 조정)**으로 칠해 유사 유형 핀들의 배치를 한눈에 알 수 있도록 한다. 단, 화면을 축소하여 핀 사이의 여유 공간이 적을 때는 주변 영역 표시를 생략한다.
- 연결기 부품 정의는 기준 방향 하나로 관리한다. 반전용 부품을 별도로 만들지 않는다.
- 프로젝트에서 사용하는 연결기별 설정에 좌우 반전 옵션을 두고 프로젝트에 저장한다. 같은 부품을 사용하는 연결기라도 서로 다른 반전 상태를 가질 수 있다.
- 반전은 표시 위치에 적용하며 부품 원본 좌표, 핀 번호와 신호 할당의 대응 관계는 바꾸지 않는다. 부품 교체와 달리 반전 옵션 변경은 핀 할당을 해제하지 않는다.

### 2.4 신호 목록표 표시
- 핀맵 뷰 옆에 선택한 연결기의 신호 목록을 표 형태로 표시한다.
- 표에는 할당 핀 번호, 신호명, 신호 카테고리(신호유형), 개별 색상 등의 기본 정보를 포함한다.
- 신호 카테고리(신호유형)는 **입력 가능한 콤보 박스**로 편집한다. 기본 항목을 제공하며, 사용자가 목록에 없는 이름을 입력하면 새로운 신호유형이 추가된다.
- 미할당 신호도 같은 표에서 조회·편집한다.
- 신호표의 마지막에는 항상 입력용 빈 행 하나를 둔다. 마지막 행에 신호를 입력하면 다음 빈 행을 자동으로 추가한다. 입력용 빈 행 자체는 신호로 취급하지 않는다.

### 2.5 양방향 선택 동기화 (하이라이트)
- **핀맵 뷰 → 신호 목록 표**: 캔버스에서 특정 핀을 선택하면 신호 목록 표에서는 **선택된 그 핀에 해당하는 행만** 선택·하이라이트된다(동일 신호를 사용하는 다른 핀의 행은 함께 선택하지 않는다).
- **신호 목록 표 → 핀맵 뷰**: 표에서 특정 행을 선택하면 캔버스의 해당 핀이 함께 선택되며, 제2.3절에 따라 동일 신호 핀들의 굵은 외곽선과 같은 카테고리 핀들의 주변 연한 배경이 표시된다.
- 미할당 신호에는 대응하는 핀이 없으므로 특정 핀을 선택한 것처럼 표시하지 않는다.
- 여러 신호가 같은 핀에 중복 할당된 오류 상태에서 해당 핀을 선택하면, 신호표에서 그 핀 번호가 할당된 행 중 **가장 먼저 나오는 신호 행**이 선택·하이라이트된다.

### 2.6 신호 할당, 변경 및 삭제
- 신호 목록과 신호표는 연결기별로 관리한다. 프로젝트 전체 공통 신호 목록은 보류한다.
- **신호 목록표에서 편집**: 신호는 이 표에서만 생성한다. 신호명 드롭다운에서 해당 연결기의 기존 신호를 선택하면 카테고리·개별 색상 등 속성도 함께 적용한다.
- 같은 신호를 여러 행에서 선택해 여러 핀에 할당할 수 있다. 같은 연결기 안에서는 하나의 신호로 관리하므로 신호명·카테고리·개별 색상 변경은 그 신호를 사용하는 모든 행과 핀에 반영한다.
- **신호 행 삭제**: 실수로 인한 삭제를 방지하기 위해 `Delete` 키는 사용하지 않는다. 신호표에서 **행의 헤더(제일 좌측 핸들 영역)를 선택한 후 마우스 오른쪽 버튼(우클릭) 컨텍스트 메뉴**를 통해 삭제한다. 하나만 할당(사용)된 신호는 해당 행을 지우면 신호도 함께 사라지고, 여러 행에 사용된 신호는 선택한 행만 지우고 다른 행과 신호는 그대로 유지한다.
- **핀맵 뷰에서 할당**: 핀을 **마우스 오른쪽 버튼(우클릭)**으로 클릭해 컨텍스트 메뉴에서 해당 연결기의 기존 신호 목록을 골라 할당(또는 해제)한다. 핀맵에서는 새 신호를 생성하지 않는다.
- 한쪽에서 변경된 내용은 즉시 다른 쪽 뷰와 색상에 반영된다.

### 2.7 연결기 부품 교체
- 프로젝트의 연결기가 사용하는 부품을 다른 부품으로 교체할 수 있다.
- 부품을 교체해도 연결기 식별자와 기존 신호표의 신호명·카테고리 등 신호 정보는 유지한다.
- 기존 핀 할당은 **모두 해제**한다. 새 부품에 같은 핀 번호가 있어도 자동으로 할당하지 않는다.
- 핀맵은 새 부품의 외형과 핀 배치로 바뀌며, 새 부품의 모든 핀은 미할당 상태로 시작한다.
- 사용자는 유지된 신호표에서 새 부품의 핀 번호를 다시 할당한다.

### 2.8 핀 번호 입력과 중복 검증
- 신호표의 핀 번호는 **입력 가능한 콤보 박스**로 편집한다.
- 핀 번호는 숫자뿐 아니라 알파벳 등 문자가 포함된 번호(예: `A`, `B`, `A1`)도 지원한다.
- 연결기 부품이 정해지면 **해당 연결기에 존재하는 핀 번호만 사용 가능**하다. 사용자가 직접 입력하거나 드롭다운에서 선택할 수 있으며, 부품에 없는 핀 번호를 직접 입력하면 입력을 거부한다.
- 부품 교체 후 드롭다운에는 새 부품의 핀 목록을 표시한다.
- 같은 연결기 안에서 여러 신호 행에 같은 핀 번호를 할당하면 중복을 검사하고 붉은 계열 배경색으로 표시한다(캔버스의 해당 핀도 가운데를 붉은 계열로 칠하고 `"신호 중복"`으로 표시).
- 중복된 모든 행의 핀 번호 셀을 표시 대상으로 하며, 중복이 해소되면 정상 표시로 돌아온다.
- 빈 핀 번호는 미할당 상태이며 중복으로 판단하지 않는다. 서로 다른 연결기의 같은 핀 번호도 중복이 아니다.

### 2.9 저장과 상태 표시
- 중복 할당 오류가 남아 있어도 프로젝트를 저장할 수 있다. 저장 후 다시 열 때도 신호와 할당 상태를 유지하고 중복 상태를 표시한다.
- 변경사항이 있는 상태에서 프로그램을 종료하려고 하면 저장 여부를 묻는다. 메인 화면과 연결기 편집기 화면을 전환할 때는 저장 여부를 묻지 않는다.
- 상태바에는 프로젝트 전체의 중복 할당 경고 수를 표시한다. 중복된 핀 하나를 경고 한 건으로 집계하며, 중복 신호 행 개수와 구분한다.
- 경고 수에는 중복 할당만 포함한다. 미할당 신호나 부품 미지정 등 설계 중인 상태는 정보·참고 수준으로 표시한다.

## 3. 화면 구성 및 조작 방식 (UI / UX)

### 3.1 기본 레이아웃과 창 관리
- 왼쪽 프로젝트 사이드바와 메인 작업 영역(핀맵 뷰, 신호 목록표)으로 구성한다.
- **사이드바와 각 창 영역은 크기를 자유롭게 조정**할 수 있으며, **도킹(Docking) 및 플로팅(Floating, 창 분리)**이 가능하도록 구성한다.

| 영역 | 표시 내용과 기능 |
| --- | --- |
| 프로젝트 사이드바 | 연결기 식별자 목록, 연결기 추가·제거, 작업할 연결기 선택 |
| 메인 화면 좌측 (핀맵 뷰) | 상단 헤더 바(연결기 정보, 부품 변경, 좌우 반전, 전체 보기) 및 선택한 연결기의 외형·핀 배열·신호 시각화 캔버스 |
| 메인 화면 우측 (신호표) | 선택한 연결기의 신호 목록, 핀 번호 할당, 신호명·카테고리(신호유형) 편집, 행 헤더 우클릭 삭제 |

- 연결기를 선택하면 메인 화면의 핀맵과 신호표가 함께 해당 연결기로 전환된다.

### 3.2 주요 작업 흐름
1. 프로젝트 사이드바에서 연결기 추가를 선택한다.
2. 프로젝트 내 고유 식별자를 정하고 부품 목록에서 연결기를 지정한다.
3. 추가된 연결기를 선택하면 메인 화면 좌측에 핀맵, 우측에 신호표가 나타난다.
4. 신호표에서 연결기에 있는 핀 번호를 입력·선택하거나, 핀맵에서 핀을 우클릭해 신호를 할당한다. 중복 할당은 신호표의 붉은 배경색과 핀맵의 붉은 핀(`"신호 중복"`)으로 확인한다.
5. 중앙 핀맵 상단 헤더 바에서 좌우 반전을 전환하거나 부품을 교체할 수 있다. 부품을 교체하면 신호표는 유지되고 핀 할당은 모두 해제되며, 새 핀 목록을 기준으로 다시 할당한다.
- 부품 지정 전에는 연결기 항목을 선택하고 신호표부터 작성할 수 있다.

### 3.3 핀맵 뷰 캔버스 조작 (CAD 스타일 내비게이션)
핀 수가 많거나 조밀한 연결기도 편하게 볼 수 있도록 CAD 프로그램과 유사한 마우스·키보드 조작을 지원한다.
- **확대 / 축소 (Zoom)**: 마우스 휠 스크롤(커서 위치 기준 확대/축소) 및 키보드 단축키 지원. 충분히 확대하면 핀 번호와 함께 할당된 신호명을 표시한다.
- **화면 이동 (Panning)**: 마우스 드래그(휠 버튼 클릭 드래그 또는 스페이스바 조합 드래그 등) 및 키보드 방향키 이동 (핀 위에서의 우클릭은 신호 할당 컨텍스트 메뉴에 사용)
- **전체 보기 (Fit to View)**: 중앙 핀맵 캔버스 상단 헤더 바의 전체 보기 버튼(또는 단축키)으로 연결기 전체가 화면에 맞게 들어오도록 배율과 위치를 초기화하는 기능

### 3.4 연결기 부품 데이터베이스와 편집 화면
- 전연결기는 자체 연결기 부품 데이터베이스를 유지한다.
- 연결기 편집기를 선택하면 메인 작업 화면 전체를 별도의 편집 화면 구성으로 전환한다. 별도 실행 프로그램으로 분리하지 않으며, 화면 전환 시에는 저장 여부를 묻지 않는다.
- 부품 목록에서 선택한 부품 정보만 가져오기·내보내기 할 수 있다. 프로젝트의 신호 목록과 핀 할당은 부품 내보내기에 포함하지 않는다.
- 부품을 가져올 때 동일한 부품이 이미 있으면 경고 메시지를 띄워 **덮어쓸지 이름을 바꾸어 추가할지** 묻는다.
- 편집기는 부품 정보, 핀 번호·좌표, 핀 추가·이동, 바둑판·원형 등 **자동 배치**와 **연결기 외곽 그리기** 기능을 제공한다.
- 기존 전연결 연결기 편집기의 통일성 없는 UI를 그대로 따르지 않고, 상용 CAD 프로그램의 조작 방식을 참고하여 외곽 그리기·핀 추가·자동 배치 등의 UI 통일성과 조작성을 개선한다.

### 3.5 기본 그리드와 스냅
- 편집 화면의 그리드 표시와 스냅은 **처음부터 켜진 상태**로 제공한다. 사용자가 간격과 켜짐 상태를 조정할 수 있도록 한다.
- **그리드에 맞지 않는 좌표의 핀도 허용**한다. 단, **그리드와 스냅이 켜져 있을 때 핀을 마우스로 이동시키면 그리드에 맞게 좌표가 변경(스냅)**되도록 한다.
- 다각형 외곽은 꼭짓점을, 원형 외곽은 중심과 반지름을 기준으로 편집·스냅한다. 원형의 곡선 전체를 격자점으로 바꾸거나 다각형으로 변환하지 않는다.
- 좌표 정밀도와 기본 그리드 간격 수치는 구현하면서 검토한다. 좌표는 논리적 표시용이며 제작 치수로 사용하지 않는다.

### 3.6 기본 제공 연결기
- 전연결의 기본 연결기 구성을 참고하여 자체 부품 데이터베이스에 다음 27종을 기본 제공한다.

| 종류 | 구성 | 개수 |
| --- | --- | --- |
| D-SUB SD | 9·15·25·37·50핀 | 5종 |
| D-SUB HD | 15·26·44·62·78핀 | 5종 |
| D38999 Series IV | B·C·D·E·F·G·H·J 셸의 `-35` 배열 | 8종 |
| Micro-D MDM | 9·15·21·25·31·37·51·69·100핀 | 9종 |

- 참고 근거는 전연결 저장소의 `docs/default-connector-library.md`, `packages/jeonnect_core/connector/defaults.py`와 D38999 접점 좌표 데이터이다. 그리드·스냅은 `docs/connector-library.md`와 `apps/jeonnect/connector_editor.py`를 참고한다.
- 참고 원본 저장소는 수정하지 않는다.

## 4. 개발·배포 방향 및 참고 저장소

### 4.1 개발·배포 방향
- **개발 환경과 실행 환경 모두 Windows와 Linux 양쪽에서 가능**해야 한다.
- 개발 기술로 Python과 PySide6를 사용한다. 아직 의존성 설치나 애플리케이션 구현은 하지 않았다.
- 각 운영체제에서 Python을 별도 설치하지 않아도 실행할 수 있는 단일 실행 파일 배포(PyInstaller 등)를 검토한다. Windows용 `.exe`는 Windows에서, Linux용 실행 파일은 Linux에서 각각 빌드·검증한다.
- 개발 중 폴더 형태로 검증한 뒤 배포 시 단일 파일로 묶는 방안을 검토한다.

### 4.2 참고 저장소와 작업 공유
- 개발 대상은 `hankjeon/jeonnector`이다.
- `hankjeon/jeonnect`는 코드·문서·구조를 읽는 **참고 전용** 저장소이다. 수정·커밋·푸시하지 않으며, 그 저장소의 기술 구성이나 데이터 모델을 임의로 도입하지 않는다.
- 클라우드와 로컬 작업은 GitHub를 통해 커밋·푸시·풀하여 공유한다. 작업 시작 전 원격 `main`을 확인하고, 완료된 변경과 인수인계 문서를 함께 관리한다.
- 커밋하지 않은 파일과 Git에서 제외한 파일은 이 방식으로 전달되지 않는다. Python 가상환경과 설치된 패키지는 각 작업 환경에서 별도로 준비한다.
