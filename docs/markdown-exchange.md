# 신호표 교환 및 부품 없는 핀 번호 설계

> 상태: **구현 완료·Linux 오프스크린 검증 완료**.
>
> 마크다운 가져오기·내보내기, 템플릿 만들기, 신호명 규칙 확장, 부품 없는 핀 번호와 불일치 경고를 구현했다. 변경 전 동작과의 비교는 [기존 설계 문서](design.md) 제6.4절에 정리한다. Windows 실제 화면 검증은 수행하지 않았다.

## 1. 목적과 범위 (확정)

- 마크다운으로 연결기별 신호표를 먼저 작성하고, 나중에 부품 편집기로 물리 배치를 만들어 연결할 수 있게 한다.
- 파일 하나는 연결기 하나를 표현한다. 파일 가져오기는 현재 프로젝트에 연결기 하나를, 폴더 가져오기는 파일별로 여러 연결기를 추가한다.
- 이번 대상은 마크다운이다. CSV·엑셀은 추후 추가하되 메뉴와 처리 계층은 형식 확장을 고려한다. 해당 형식의 실제 구현과 외부 의존성 추가는 이번 범위가 아니다.
- 개발 중이므로 구버전 호환성·마이그레이션·호환성 보호를 위한 저장 형식 버전 증가는 요구하지 않는다. 이번 설계만을 이유로 기존 호환 처리 기능을 제거하는 작업도 하지 않는다.

## 2. 신호명 규칙 (구현 완료)

| 항목 | 규칙 |
| --- | --- |
| 허용 문자 | 영문자, 숫자, `_`, `+`, `-`, `#`, `/`, `.` |
| 첫 문자 | 영문자, 숫자, `+`, `-` 중 하나 |
| 필수 구성 | 영문자나 숫자를 하나 이상 포함. 기호만 있는 이름은 금지 |
| 공백 | 앞뒤 공백은 제거하고 내부 공백은 금지 |
| 길이 | 정규화한 이름 기준 최대 32자, 빈 이름 금지 |
| 대소문자 | 영문을 대문자로 정규화하여 비교·저장 |

- 예: `+5V`, `-12V`, `485_TX`, `DATA+`, `DATA-`, `RESET#`, `RD/WR`, `P1.0`, `UART_TX`.
- `DATA+`와 `DATA_P`, `RESET#`과 `RESET_N`은 별개 이름이다. 표기를 추측하여 변환하거나 병합하지 않는다.
- 연결기 식별자는 기존 규칙을 유지한다: 영문자로 시작하고 영문 대문자·숫자·밑줄만 사용하며 최대 32자, 영문 대문자로 정규화한다.
- 신호유형도 기존 규칙을 유지한다: 영문자 또는 한글로 시작하고 영문 대문자·한글·숫자·밑줄만 사용하며 최대 32자, 내부 공백 금지, 영문 대문자 정규화.
- 신호명과 연결기 식별자의 검증 함수를 분리했다. 신호명 확장이 다른 이름 규칙까지 바꾸지 않는다.

## 3. 신호표와 부품의 관계 (구현 완료)

### 3.1 정보 소유와 보존

- 핀 번호는 연결기 신호표가 소유한다. 연결기 부품은 핀 번호에 대한 좌표·외곽 등 물리 배치를 제공한다.
- 부품이 없어도 핀 번호를 직접 입력하고 저장·복원할 수 있다. 임시 부품을 자동 생성하지 않는다.
- 선택한 부품에 없는 번호도 형식이 올바르면 입력을 허용하고 불일치로 표시한다. 부품 존재 검증과 번호 형식 검증을 분리한다.
- 핀 번호의 대소문자 구분·공백 금지·자연 정렬은 기존 규칙을 유지한다.
- 핀 번호가 빈 신호만 미할당이다. 부품이 없거나 부품과 불일치한다는 이유로 미할당으로 바꾸거나 행을 병합하지 않는다.

### 3.2 부품 변경에 따른 처리

| 작업 | 핀 번호와 신호 처리 |
| --- | --- |
| 최초 부품 선택 | 기존 번호 유지, 같은 번호의 부품 핀에 대응 |
| 다른 부품으로 교체 | 기존 번호 유지, 새 부품과 대응 여부 재검사 |
| 부품 연결 해제 | 번호·신호 유지, 핀맵만 부품 미선택 상태 |
| 같은 부품의 핀 이동·추가 | 번호 유지, 대응 여부 재검사 |
| 같은 부품의 핀 삭제·번호 변경 | 신호표 원래 번호 유지, 대응되지 않는 번호에 경고 |
| 해당 번호의 핀 복구·추가 또는 올바른 부품 선택 | 자동으로 대응하고 불일치 경고 해소 |

- 부품 교체 확인 문구는 기존의 ‘모든 할당 해제’ 대신 ‘기존 핀 번호 유지 및 같은 번호에 대응’으로 변경한다. 같은 번호라고 물리적 역할까지 같다는 뜻은 아니므로 결과 검토를 안내한다.
- 부품 정의 변경 반영 시에도 핀 번호를 삭제하지 않는다. 기존의 삭제 핀 할당 해제 절차를 번호 보존·불일치 안내로 변경한다.
- 핀맵은 선택된 부품에 실제 존재하는 핀만 그린다. 불일치 번호를 임의 좌표에 그리지 않는다.

### 3.3 표의 표시와 선택

| 상태 | 표시 |
| --- | --- |
| 번호 없음 | 기존처럼 빈칸·미할당 |
| 번호 있음·부품 미선택 | 번호 정상 표시, 핀맵에 부품 미선택 안내. 오류로 취급하지 않음 |
| 번호 있음·선택 부품에 해당 핀 있음 | 정상 표시, 핀맵 연동 |
| 번호 있음·선택 부품에 해당 핀 없음 | 핀 번호 칸에 주황색 계열 경고 배경, 툴팁으로 사유 표시 |
| 같은 번호에 서로 다른 신호 | 부품 유무와 무관하게 기존 빨간색 계열 신호 중복 표시 |
| 부품 불일치·신호 중복 동시 발생 | 빨간색 우선, 툴팁에는 두 사유 모두 표시 |

- 미할당·부품 미선택·불일치 행을 선택하면 이전 핀맵 강조를 해제하여 다른 핀이 선택된 것처럼 보이지 않게 한다.
- 부품 불일치 상태는 현재 표와 부품으로 계산한다. 이를 위한 별도의 영구 상태 필드는 필요성을 확인하기 전 추가하지 않는다.
- 부품 불일치 경고는 표에만 표시한다. 상태바·사이드바는 기존 신호 중복 집계를 유지하며 불일치를 합산하지 않는다.

## 4. 마크다운 문서 규격

### 4.1 읽을 정보 (확정)

- 프로그램이 사용하는 정보는 **식별자와 신호표뿐**이다. 부품명은 가져오기 항목과 템플릿에서 제외한다.
- 제목, 설명, 이미지, 다른 표 등은 문서 자체의 내용이며 프로젝트 데이터로 가져오지 않는다. 가져오기는 원본 파일을 수정하지 않는다.
- `- 식별자 : J1` 같은 목록 항목에서 식별자를 읽는다. `**식별자**`처럼 굵게 쓴 항목 이름과 `` `J1` ``처럼 백틱으로 감싼 값도 읽는다. 식별자가 없거나 값이 비어 있으면 자동 부여한다.
- 신호표의 열은 `핀 번호`, `신호명`, `신호유형`, `색상`이다. 신호명 열만 필수이며 제목으로 열을 인식하므로 순서를 바꿀 수 있다. 열 제목의 공백은 무시한다(예: `핀번호`, `신호 유형`). 인식하지 못한 열은 무시하고 미리보기에 경고로 열 제목을 안내한다.
- 핀 번호만 있고 신호명이 빈 행은 가져오지 않고, 파일마다 경고 한 건으로 해당 핀 번호와 줄 번호를 안내한다. 핀 번호도 신호명도 없는데 신호유형·색상만 있는 행은 오류이다.
- 표 바로 다음 줄에 빈 줄 없이 글을 쓰면 표의 행으로 보아 열 개수 오류가 나며, 오류 문구로 빈 줄을 넣도록 안내한다.
- 백틱으로 감싼 신호명과 감싸지 않은 신호명을 모두 읽는다. 감싸는 백틱은 실제 신호명에 포함하지 않는다.
- 백틱은 셀 전체를 감싸는 형태를 지원한다. 코드 셀 안의 엔티티·역슬래시·주석 모양 문자열은 일반 문법으로 해제하지 않는다. 일부만 코드로 감싼 혼합 표현은 값을 추측하지 않고 오류로 안내한다.
- 코드 울타리와 네 칸·탭 들여쓰기 예제는 가져오지 않는다. 신호명만 있는 단일 열 표에서는 데이터 행의 바깥 구분자를 생략할 수 있다.
- 내보낼 때는 신호명을 백틱으로 감싸 원문 표시를 보존한다. 핀 번호는 읽기 쉽도록 표 구분자(`|`)·역슬래시·백틱만 역슬래시로, `&`·`<`·`>`는 HTML 문자 참조로 바꾸고 나머지는 그대로 쓴다(예: `A-1`, `1.2`).

### 4.2 작성 양식 예시

아래는 `파일 → 내보내기 → 마크다운 → 템플릿 만들기…`에서 생성하는 양식이다. 예시 행은 자동으로 무시되는 주석이 아니라 실제로 가져오는 데이터이므로 사용자가 수정·삭제해야 한다.

````markdown
# 연결기 신호표

이곳에는 용도와 주의사항 등 자유로운 설명을 작성합니다.
아래 예시 행을 실제 신호로 수정하거나 삭제하세요.
식별자를 비우면 자동으로 부여합니다. 부품 없이도 핀 번호를 보존합니다.
색상은 #RRGGBB 형식이며 빈칸이면 개별 색상 없음입니다.

- 식별자 :

| 핀 번호 | 신호명 | 신호유형 | 색상 |
| --- | --- | --- | --- |
| 1 | `+5V` | POWER | |
| 2 | `GND` | GROUND | |
| 3 | `DATA+` | DISCRETE | #2563EB |
| 4 | `RESET#` | DISCRETE | |
| | `SPARE` | | |
````

### 4.3 신호유형과 색상 (확정)

- 신호유형은 이름을 기존 규칙으로 정규화하여 프로젝트의 같은 유형을 재사용한다. 기존 유형 색상은 유지한다.
- 없는 유형은 새로 생성하고 유형 색상은 기본 ‘없음’으로 설정한다. 유형 칸이 비어 있으면 유형 없음이다.
- 색상 칸에 값이 있으면 신호 개별 색상으로 적용하고 유형 색상은 바꾸지 않는다.
- 개별 색상이 없으면 유형 색상을 사용한다. 둘 다 없을 때의 핀 표시는 기존 규칙을 따른다.
- 색상 값은 `#RRGGBB` 형식의 6자리 16진수만 허용한다. 영문 대소문자는 모두 허용한다.
- 빈 색상 칸은 개별 색상 없음이다. 색상 이름, 3자리 축약형, 투명도를 포함한 형식은 허용하지 않는다.
- 잘못된 색상은 오류로 안내하며 조용히 생략하지 않는다.
- 같은 신호명의 빈 유형·색상은 다른 행의 명시값을 따르고, 서로 다른 명시값이 있으면 파일 오류로 안내한다. 같은 핀·같은 신호명의 완전 중복 행은 속성 검사 후 합치고 안내한다.

## 5. 가져오기와 식별자 (확정)

- 파일 하나를 가져오면 새 연결기 하나를 추가한다. 폴더를 가져오면 마크다운 파일별로 연결기를 추가한다.
- 기존 연결기를 자동 덮어쓰기하거나 병합하지 않는다.
- 유효한 식별자가 있으면 사용하고, 없거나 비어 있으면 사용하지 않는 `J1`, `J2`, `J3` 순서로 부여한다.
- 명시된 식별자가 겹치면 `_1`, `_2`, `_3` 순으로 접미사를 붙여 사용하지 않는 이름을 부여한다.
- 가져온 연결기는 부품 없이 신호표·핀 번호를 보유할 수 있다. 부품은 이후 프로그램에서 선택한다.
- 폴더 바로 아래 `.md` 파일을 파일명 자연 정렬로 검사한다. 명시 식별자를 먼저 예약한 뒤 자동 번호를 배정하며, 잘못된 식별자·접미사를 붙이면 32자를 넘는 이름은 오류로 안내한다.
- 미리보기에서 정상 파일을 선택하여 한 번에 등록한다. 파일 오류의 행 번호와 사유, 중복 경고를 표시하고 오류 파일은 선택할 수 없게 한다. 신호표 없는 문서는 안내 후 등록 대상에서 제외한다. 원본 파일과 취소한 가져오기는 프로젝트를 변경하지 않는다.
- 가져오기 전체는 실행 취소 한 단계이다. 가져오기·신호표 내보내기 전 미완료 입력은 기존 추가·버리기·취소 절차로 처리한다. 여기서 사용자가 명시적으로 확정한 입력이나 편집기 부품 반영은 별도 편집이다.

## 6. 메뉴와 내보내기 (구현 완료)

```text
파일
 ├ 새로 만들기
 ├ 열기…
 ├ 최근 파일
 ├ 저장
 ├ 다른 이름으로 저장…
 ├ ─────────────
 ├ 가져오기
 │   └ 마크다운
 │       ├ 파일 가져오기…
 │       └ 폴더 가져오기…
 ├ 내보내기
 │   └ 마크다운
 │       ├ 선택 연결기 내보내기…
 │       ├ 전체 연결기 내보내기…
 │       ├ ─────────────
 │       └ 템플릿 만들기…
 ├ ─────────────
 └ 종료
```

- 선택 연결기는 마크다운 파일 하나로, 전체 연결기는 선택 폴더 안의 연결기별 파일로 내보낸다.
- 선택 연결기가 없으면 선택 내보내기, 연결기가 하나도 없으면 전체 내보내기를 비활성화한다.
- 템플릿 만들기는 저장 위치를 선택해 작성용 `.md` 파일 하나를 생성한다. 프로젝트·연결기가 없어도 사용할 수 있고 프로젝트는 변경하지 않는다.
- 템플릿에는 식별자·신호표·작성 안내·특수문자와 미할당 예시를 포함한다. 부품명은 포함하지 않는다.
- 기존 파일을 대상으로 내보내거나 템플릿을 만들 때는 덮어쓰기 전에 확인한다.
- 내보내기는 내용을 완전히 기록한 경우에만 대상 파일을 교체한다. 기록 도중 실패하면 기존 문서를 보존하며, 직접 덮어쓰기 대체 동작은 사용하지 않는다.
- CSV·엑셀은 추후 가져오기·내보내기 아래에 마크다운과 나란히 추가한다. 미지원 형식의 비활성 메뉴는 미리 만들지 않는다.
- 형식별 읽기·쓰기와 공통 검증·식별자 처리·연결기 등록을 분리한다. 향후 형식마다 서로 다른 파일·시트 구성을 지원할 수 있도록 하되, 미사용 형식의 선행 구현이나 불필요한 추상화는 하지 않는다.
- 마크다운 교환은 `.jnc` 전체 프로젝트 저장을 대체하지 않는다. 부품의 물리 배치와 별도 유형 색상표를 교환하는 기능은 이번 범위에 포함하지 않는다.

## 7. 검증 범위와 결과

Linux·PySide6 6.12.0·Qt 오프스크린 환경에서 전체 **221개 테스트 통과**(검토 후속 수정 포함). 아래 항목을 자동 테스트와 실제 오프스크린 실행으로 검증했다. Windows 실제 화면 조작은 미검증이다.

- 확장 신호명의 허용·거부·정규화 및 연결기 식별자·신호유형 규칙의 독립성.
- 부품 없는 번호의 입력·편집·저장·복원·정렬·신호 중복 표시.
- 최초 부품 선택, 교체, 연결 해제, 같은 부품 핀 삭제·번호 변경·복구 시 번호 보존.
- 불일치·중복·동시 발생의 색상과 툴팁, 경고 해소 및 핀맵 선택 해제.
- 식별자 사용·자동 부여·접미사 충돌, 파일·폴더 가져오기, 신호유형 재사용·신규 생성, 개별 색상.
- 원본 문서 미수정, 자유 설명 무시, 백틱 유무와 특수문자 신호명 처리.
- 선택·전체 내보내기, 재가져오기 시 식별자 충돌 규칙과 신호표 보존, 템플릿 생성·덮어쓰기 확인.
- 메뉴 활성 상태, 미완료 입력 보호, 가져오기 전체의 실행 취소·다시 실행.
- 관련 모델·저장·화면 회귀 테스트. 구버전 호환성 검증은 요구하지 않는다.
- 실제 템플릿 기반 가져오기 후 부품 연결·주황색 불일치 표시·원문 보존·`.jnc` 저장 후 복원·마크다운 재가져오기·실행 취소와 다시 실행을 확인했다. 미리보기와 메인 화면을 렌더링하여 표시도 확인했다.
- 전체 내보내기의 파일별 성공·실패 집계와 덮어쓰기 거부 시 기존 내용 보존을 자동 테스트로 확인했다. 새 외부 의존성은 추가하지 않았다.
- 검토 후속 수정: 열 제목 공백 무시와 미인식 열 경고, 신호명 없는 핀 번호 행 경고 후 제외, 굵은 식별자 항목·백틱 식별자 값, 읽기 쉬운 핀 번호 내보내기, 표 다음 빈 줄 안내를 회귀 테스트로 확인했다. 미리보기 화면에서 경고 여러 줄이 모두 보이는 것을 렌더링으로 확인했다.
- 독립 검토에서 발견한 단일 열 표 행 누락·들여쓰기 예제 오인식·인라인 코드 문자 변형을 회귀 테스트로 수정했다. 중간 기록 실패 시 기존 문서 보존, 실제 미리보기 버튼으로 정상 파일 두 개 등록 후 한 번에 실행 취소도 검증했다.

## 8. 세부 정책 (확정)

사용자가 구현 지시 후 제8절의 권장안과 식별자·신호표만 새 문서로 내보내는 정책을 확정했다. 부품 불일치 경고는 표에만 추가하고 상태바·사이드바의 기존 집계는 유지한다.

| 항목 | 확정 정책 |
| --- | --- |
| 표 열 인식 | 신호명 열만 필수, 나머지는 선택. 제목으로 열을 인식하여 순서 변경 허용 |
| 표 구분 | 신호표가 없는 문서는 안내 후 건너뛰고, 인식되는 신호표가 여러 개면 오류. 설명용 다른 표는 제외 |
| 폴더 범위·순서 | 폴더 바로 아래 `.md`만 파일명 자연 정렬로 처리. 하위 폴더 제외 |
| 식별자 배정 | 전체 파일의 명시 식별자를 먼저 예약한 뒤 자동 번호를 배정. 잘못된 명시 식별자와 접미사를 붙이면 32자를 넘는 경우는 자동 절단하지 않고 안내 |
| 미리보기·오류 | 최종 식별자·신호 수·파일명·줄 번호·원인을 표시. 파일 단위 검증 후 정상 파일만 선택 등록 가능. 오류 행만 몰래 누락하지 않음 |
| 공유 속성 충돌 | 동일 신호명에서 빈 유형·색상은 다른 행의 명시값을 따름. 서로 다른 명시값은 오류 |
| 완전 중복 행 | 같은 핀 번호·같은 신호명은 속성 충돌 검사 후 한 행으로 합치고 안내 |
| 일괄 실행 취소 | 최종 가져오기 전체를 한 단계로 되돌림. 취소·미리보기만으로 프로젝트나 유형 목록을 변경하지 않음 |
| 경고와 등록 | 신호 중복·부품 불일치는 경고로 두고 등록 허용. 형식 오류와 구분 |
| 내보내기 세부 | 파일명은 식별자 기반, 행은 화면 정렬과 무관한 핀 번호 자연 정렬. 전체 내보내기는 파일별 성공·실패 건수와 실패 경로를 안내 |
| 설명 내용의 재출력 | 가져오기 시 원본 미수정·설명 비수집. 내보내기는 식별자·표만으로 새 문서를 생성하고 원문 설명은 재현하지 않음. 기존 파일 덮어쓰기는 확인 필요 |
| 경고 집계 | 부품 불일치는 표의 주황색 경고로 표시. 상태바·사이드바 기존 신호 중복 집계는 유지 |
| 추가 구문 세부 | UTF-8 및 UTF-8 BOM 허용. 반복 식별자 항목은 오류, 빈 신호표는 빈 연결기 허용, 완전히 빈 데이터 행은 무시, 알 수 없는 열은 경고 후 무시, 신호명 없는 핀 번호 행은 경고 후 제외. 열 제목 공백 무시. 코드 블록·주석 안 예시는 가져오지 않음 |

기존 연결기 갱신·병합, 신호표로 부품 자동 생성은 이번에 구현하도록 승인된 기능이 아니다. 필요하면 별도로 협의한다.
